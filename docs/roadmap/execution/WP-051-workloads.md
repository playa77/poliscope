# WP-051 coupled workload and limits

The owner accepted this optimization as sufficient for the prototype on
2026-10-27 and authorized the complete PR. Further optimization and unrun final
performance validation are deferred until all packages and thorough project
testing are complete. Budget misses below remain measured misses.

All fixtures are synthetic engineering models. Twelve domain labels exercise
shared orchestration; they assert no scientific social effects. The exact DEC-06
scope/cohort/asset/decision/relationship counts remain unchanged. Cohorts have two
explicit overlapping memberships; their physical stock is never copied by view.

## Static arithmetic

`dec06-coupled-static-v1` activates 300 / 3,000 instances. Two finite consumers
share one canonical resource and labor budget, two instances form a declared
four-node linear feedback component, and the remainder form scope-local chains
across all twelve domain tags. Changing the authored seed from 100 to 101 changes
the first scope's dependent chain. Every cold sample computes the complete result;
warm samples still prepare full input, model, review, numeric and realization
identity before any cache hit. Candidate equality includes the full report.

For zero-based chain index `i` and scope count `S`, the independent integer oracle
is `floor(i/S) + 1 + seed` when `i % S == 0`, otherwise `floor(i/S) + 1`.
The feedback equations `x = y/2 + 1`, `y = x/2 + 1` give `x = y = 2` exactly.
Removing the solver must retain explicit unresolved feedback, with no invented
successful account finalization. Solver operation limits and failures retain their
existing independent regressions.

The finite book uses WP-019's literal oracle: initial stock 100, finite import 10,
initial loss 10, two requests of 80 and a protected hold of 40. Priority allocates
60 and 40; product is 70, residual 20, transformation loss 10, and labor closing is
2. This numerical fixture is separate from the increment-chain observations.

## Dynamic arithmetic

`dec06-coupled-dynamic-v1` adds twelve explicitly owned transition-only bindings
to the same scaled world, with one shared material budget and one shared labor
budget, each initially 10,000. There is no implicit capacity renewal. Every daily
boundary executes production proposal, finite reduction, resolve, independent
account validation and transactional confirmation. Dynamic production feeds the
first static chain: every day changes real dependent observations.

Nine series request one unit daily. Of the remaining three, weekly delivery
requests seven units each seventh day, seasonal processing requests 91 units each
91st day, and the annual service update requests 364 units each 364th day. A dated
disruption enables one extra response unit on days 100–109; the day-110 repair
removes it. Both event preconditions and retained outcomes are checked.

For day `d`, total actual consumption is independently derived as:

`T = 9d + 7 floor(d/7) + 91 floor(d/91) + 364 floor(d/364) + clamp(d-99, 0, 10)`.

Material and labor closings are `10000-T`, product is `7T/10`, residual is `2T/10`,
and loss is `T/10`. At day 365, `T=4387`: material/labor 5613, product 3070.9,
residual 877.4 and loss 438.7. These literal/integer/Fraction expectations never
call the production allocator, solver or transition arithmetic.

Two accepted policy deltas apply to disjoint binding IDs on day 7. Repeating the
first delta with its original precondition on day 8 retains a conflict. Exclusive
policy conflicts remain visible; this fixture declares no numerical social
coefficient for them. Policy adoption does not copy the approved source revision's
stocks into the running experiment.

A compact calendar conformance route uses four scopes/cohorts/assets, sixteen
static instances and 24 edges. It must check the entire 365-day schedule and the
declared oracle, but cannot certify the full DEC-06 performance workload. No
completed 365-day receipt for that new twelve-domain fixture is claimed here. Full
classroom/exploratory requests must retain their actual completed days and any
quota status; a timed-out annual request is never reported as a completed year.

The dynamic runner now defaults to **three days / thirty seconds**. A requested
365-day classroom run stops after three measured days if its projected duration
exceeds the frozen 30-second budget. It records `annual_throughput_gate_failed`,
actual completed days, raw times and `PERF-DYNAMIC-001`. A projection is not an
annual measurement. No failed throughput gate justifies continuing a long run.

## CPU execution and validation

The target is a mid-level student PC. The engine uses the local CPU and SQLite;
these optimizations require no GPU, model server or accelerator. Repeated immutable
world construction, callbacks' full-world copies, duplicate accounting queries,
compiler graph construction and canonical JSON passes were the primary measured
costs. Numerical Decimal rules and the independent Fraction balance oracle remain.

Static geography is shared through immutable registry indexes. Compiler entries
reuse topology while binding fresh quantities and reconstructing the exact current
request identity. Only successful pure numerical leaves may be reused under their
complete input/type/context/model key; finite allocation still runs. Canonical
encoding remains byte-compatible with v1, including ordered operands and additive
field exceptions; differential tests retain the original encoder as the oracle.
The pinned `orjson` dependency accelerates trusted retained JSON snapshot parsing;
canonical identities continue to use the versioned engine encoder.

Callbacks receive deep read-only DTO containers, share one boundary-local view,
and still run twice to check determinism. Their independent validators still run
against actual allocations and the complete closing view. An internal advance
carries a private publication capability bound to exact candidate bytes, producer
assembly proof, context, head and validator. It avoids a second full reduction of
that same privately produced candidate. Public confirmation independently reduces
external candidates. Mutation, stale heads, replacement validators and cancellation
reject publication. The write-lock check and all state/evidence/operation writes
remain in one transaction. Tests compare the complete retained history from both
paths byte for byte, and inject failure after every storage write.

Only committed private frames may be reused; every retained chunk is read and
hash-checked again before use. Public reads and previews are detached. Progress
reads a small immutable projection committed with its boundary, with a verified
legacy fallback. Boundary state/evidence manifests may share content-addressed
chunks; existing manifests remain readable, and corrupt/missing chunks fail closed.

## Admission, pages, caching and cancellation

Trusted-host ingestion uses ordered chunks of at most 512 KiB, at most 4,096 chunks
and 32 MiB total, with an expected SHA-256, strict JSON/object-key validation and
full DTO validation before publication. This API grants no renderer file/path or
raw model execution authority. Retained snapshots keep their 64 MiB blob ceiling.
Large mutation journal bindings use a complete canonical request digest; legacy
bindings within the original 1 MiB limit remain compatible. Replay still precedes
current-head checks, and migration recovery retains its exact context/name grant.

World pages read immutable derived blocks of at most 100 rows / 750,000 bytes.
Every block and its metadata is hash-checked; arbitrary smaller page sizes and
complete-context cursors preserve the canonical row sequence. Older revisions use
the existing verified reader. These indexes never supply simulation input and do
not replace accepted evidence. Missing/corrupt projections fail explicitly.

Evaluation results have the existing 16-entry / 64 MiB bound. Complete retained
assemblies add an eight-entry / 64 MiB bound keyed by physical output, measurements,
goals and reference content, after fresh physical identity/review preparation.
Sixteen verification markers may avoid repeating semantic closure verification
for exact previously verified bytes; every retained chunk is still read and
integrity-checked. Additional bounded disposable caches hold canonical fragments
(8 MiB leaves, 64 MiB arrays, 64 MiB documents, 16 MiB time-independent bodies),
two graph shapes (64 MiB total), read-only leaves (8 MiB), four compiled plans
(16 MiB), trace plans/reference sets (8 MiB each), reports (16 MiB), pure numerical
leaves (4 MiB), and at most two private committed frames (32 MiB serialized each).
Proof-only markers retain digests, not payloads. Public returned DTOs are detached.
Clearing caches preserves historical evidence and results. Serialized byte bounds
exclude Python overhead, registry objects and native combined process RSS.

Cooperative cancellation, time and serialized snapshot quotas abort before
publication. Nested limits cannot mask an outer caller's cancellation. The pure
subprocess host also retains its termination deadline and frame bound. Only fixed
typed quota/cancellation reasons reach the renderer; private diagnostics stay
redacted. Cancel stays available during previews and running timeline chunks.
Apply recovery uses its existing bound operation ID and never implies rollback
when confirmation is uncertain. Superseded read/preview subprocesses are aborted;
late responses cannot install an obsolete selection or candidate.

Native reference hardware, packaged Windows/Linux behavior and combined Electron
RSS remain owner-run under the project-wide waiver. Cloud receipts identify the
actual measured layer and any release-blocking performance issues.
