## Implementation and inspection

Interview contract 1 is generated from Python and named read/preview/apply/cancel
IPC calls retain existing caller, arity, 16 KiB request and 1 MiB response bounds.
One main-only candidate binds the exact typed edit, selected context and random
operation ID. Apply accepts its digest, reconstructs the full request in Python,
checks the head and uses the production atomic revision/evidence/operation ledger.
Completed requests replay before stale-head checks. Uncertain same-session replies
retain the same candidate/operation; reopening after process loss inspects confirmed
state and explicitly discards the unsaved draft. No renderer paths, changes, model
registration or operation IDs are accepted. Historical views cannot preview edits.

Twelve original synthetic prose problems offer three distinct coordination
procedures, possible benefits and costs/requirements. Origin, hypothetical evidence,
qualitative coverage, original wording, scope, dependencies and clarification remain
visible. No imported source choice is presented as a default. Player alternatives
use the same Definition/preview/archive route and remain nonexecuting qualitative
content. Resource-template population/area variants retain exact decimal strings,
nonnegative/integral-population rules, units, scope and unknown values. Authoring
refuses conditions whose registered writer is not the player. Existing goals,
mechanisms and unrelated choices are preserved.

A chosen card is an unsaved local draft. Parameter/rationale edits invalidate its
preview; switching cards preserves typed conditions/rationale. Distinct Apply,
cancel and session-local deferral are keyboard accessible. Drafts lock state-changing
navigation, folder/history selection and reconnect until explicitly resolved.
Context/scope/revision/model query identities and component lifetimes isolate late
reads. Retryable read/preview errors, stale apply refresh, uncertain Apply retries
and explicit confirmed-branch reopen have separate visible paths. Condition tables
exclude qualitative commitment metadata; readable commitments escape all text.

Every offered alternative contains the complete typed staged inputs and archived
question/option/card, scope, dependencies and coverage. Applied decisions retain
one selected alternative and a private rationale reference. Rationale payloads are
private files beside the selected store, written through fsynced, restrictive,
atomic non-overwriting staging before revision acceptance. No rationale text enters
immutable snapshots, accepted evidence or operation bindings. File identity binds
the operation and payload; failed precommit attempts can leave private orphan notes,
but previews/cancel never write them. Retry reuses an identical payload. See
`engine/poliscope_engine/INTERVIEWS.md` for layout, crash semantics and classification.
Portable projection, private-payload management and deletion UI remain WP-031/039;
raw folder copies are not classified exports. Store schema 1 and locks are unchanged.

Separate author inspection checked ownership and exact numeric inputs, independent
unknown/zero expectations, all-domain access, complete archived alternatives,
nonexecution of proposal HTML/shell strings, context/grant revocation, query keys,
draft navigation, stale heads, idempotent lost replies, private payload durability,
canonical references and readable keyboard controls. It strengthened condition
writer checks and model-keyed queries, distinct option procedures and commitment
presentation. This is SV author inspection, not independent agent review.

The packaged rapid-domain-navigation regression exposed obsolete interview reads
queued ahead of creation. Main now coalesces waiting interview reads by generation;
only the latest queued selection runs, and create/select/folder actions revoke
waiting old-context reads. An already running read completes under its original
context. Mutation and page ordering remain serialized. A deterministic blocked-read
unit case verifies latest-read selection and creation preemption; the packaged
all-domain/create/reference/reopen case exercises the actual queue behavior.

Apply preserves the selected scope while advancing the revision. If a concurrent
head removed that scope, the refreshed Python directory selects a valid fallback.
Explicit civilization/branch selection still resets scope. Packaged coverage also
applies an interview on a second scope before switching branches and reading history.

Validation uses isolated synthetic stores and no provider calls. Cloud CPU/process
contention caused early child-process deadline failures; final runtime suites run
sequentially. Cloud runner overrides use 120 s Vitest cases/10 s poll and 20 s
Playwright assertions/180 s cases (the complete interview flow has its own 240 s
budget). Numerical, identity, mutation and security assertions are unchanged.
The single-instance harness allows 10 s for the second Electron process to exit;
its 5 s cold-start deadline proved intermittent. It still requires exit code 0 and
checks the original app's secure renderer and retained store. Product handshake,
request/queue/frame limits and OS single-instance ownership are unchanged.

Native validation is Linux only, using a temporary Xorg dummy display. The
`--no-sandbox` Linux test flag is not application configuration or an OS-sandbox
certificate; application preferences retain sandbox/context isolation. Windows remains untested. Private filenames use hexadecimal leaves for portability;
that structural check does not establish native-platform validation. No full
application, scientific, imported-corpus or numerical-domain gate is claimed.
