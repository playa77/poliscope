## Analysis

The rebuilt `AppShell` renders brand, navigation and the status slot inside an
aside with `hidden … lg:flex`: below the 1024 CSS px breakpoint the entire rail
— including `role="status"` — leaves the accessibility tree and no navigation
stays reachable. The CI ARIA snapshots show the full content column with no
rail at all. Reproduction on the same Linux binary pins the mechanism to width,
not platform: `xvfb-run -s "-screen 0 1000x760"` reproduces the failing shape,
`1280x900` passes, and after the fix the previously failing three pass at
1000px. The Windows 2022 runner therefore renders the 1040×720 window at an
effective CSS width below 1024 px; any 200%-zoom session would hit the same
class the WP-058 zoom fix was already hardening.

Second finding (same session): the frozen release inventory did not cover the
shipped component sources introduced by the UI rebuild — `components/`,
`lib/utils.ts` and `components.json` fall outside `freeze_release.py`'s product
whitelist, so the fingerprint stayed at the old 665 paths while 686 real
shipped/build sources exist. Found while assembling the rc.3 byte comparison
for artifacts.json. The manifest inside each built artifact still pins every
bundled file, so the built binaries' identity is unaffected; the drift
detection contract needed completion.
