# WP-058 — From-zero UI rebuild on a ReUI/Tailwind rendering layer

Status: **in progress; foundation delivered, screen rebuild outstanding**.
Base: fetched main `77602b0` (merge of PR #130, merged WP-057). Branch
`codex/wp-058-ui-rebuild`. Owner: Hermes (default session), controlled by the
requesting repository user; one sequential agent, no collaborators. Route:
solo-validated; agent review deferred.

## Scope

The owner asked for a complete replacement of the desktop presentation layer,
not a restyle: the renderer was React 19 with one 80-line hand-written
`desktop/renderer/style.css` (green-on-charcoal), 1 827 lines of TSX across
twelve screens, no Tailwind, no component library and no design tokens. The
target look is a soft indigo/lavender dashboard: pale lavender canvas, floating
white cards with wide radii and diffuse shadows, a single saturated indigo for
action, navy ink instead of black.

Design-system adoption is a rendering-layer change, so this package is
deliberately ordered foundation first, then screens, with the working tree
building and the regression suite green at every commit.

## Colour provenance (sampled, not estimated)

The first pass took its colours from a written description of the reference
image, which was wrong in two ways the owner caught: the accent was too pale and
the canvas was a flat fill where the reference has a left-to-right wash. Both
were re-derived from the pixels with PIL:

| Role | Measurement | Token |
| --- | --- | --- |
| Canvas, left edge | median of the leftmost 3 columns over the card-free top and bottom bands | `#F1EDFC` |
| Canvas, right edge | same band on the right, used unchanged after the owner rejected the lightened variant | `#B4DCFF` |
| Primary | median of the saturated indigo cluster (hue 248°, sat 0.97), 22 124 px | `#2207D4` |

White on `#2207D4` is 10.2:1. Verified in the rendered build by capturing the
viewport at 1440 px and sampling it: left pixel `#F1EDFC` (exact) and right
pixel `#B4DCFF` (exact). The flat `--canvas-mid` fallback is the right stop on
purpose: the scrollbar gutter sits at the right edge, so a mid-point tint would
show as a stripe beside it.

Cards carry a 1 px indigo-tinted ring inside `--shadow-card` so they separate
from the blue end of the wash; the shadow tint is the sampled indigo rather than
a neutral slate.

## Delivered in this commit

- Tailwind v4 through `@tailwindcss/vite`; `components.json` registers the ReUI
  registry (`@reui` → `https://reui.io/r/{style}/{name}.json`) on the
  `radix-nova` style. Components install as owned source under `components/`.
- Design tokens (`desktop/renderer/style.css`) for the new identity, light and
  dark, mapped through `@theme inline`, plus a transitional element layer so
  screens that have not migrated already render in the new palette instead of
  keeping the green.
- Inter bundled through `@fontsource-variable/inter`; no runtime font fetch, so
  the app stays offline and the packaged content policy is unchanged.
- Shell components: floating navigation rail (`AppShell`, `NavGroup`,
  `NavItem`), content blocks (`Panel`, `Stat`, `StateBadge`, `EmptyState`,
  `ErrorNote`, `LoadingRows`, `KeyValue`), and `NativeSelect`.
- `src.tsx` now owns the active view so navigation lives in the shell;
  `workspace.tsx` keeps every existing contract, focus effect and page-scoped
  state, and renders into the new chrome.
- `@/*` resolves in vite, vitest and tsc (TypeScript 7 removed `baseUrl`; paths
  are configured without it).

## Design decisions worth keeping

- **Native selects.** The registry select is a listbox of buttons; six desktop
  regression specs drive the branch and scope pickers with `selectOption()`, and
  a native control also keeps the platform picker and type-ahead. `NativeSelect`
  styles a real `<select>` instead of replacing it.
- **One container family.** Every panel is a floating card; the 22 px radius and
  the diffuse shadow are defined once in `Panel`, not sprinkled per screen.
- **Status is never colour alone.** `StateBadge` always carries words, per the
  accessibility rules in `AGENTS.md`.

## Outstanding

1. Ten screens still render through the transitional element layer:
   `overview`, `matrix`, `atlas`, `world`, `evidence`, `uncertainty`, `timeline`,
   `design-history`, `archives`, `interview`, plus `providers` and `recovery`.
   Each needs its own commit against the token set.
2. `npm run test:desktop` (Playwright) was **not** run: it requires
   `npm run package` and a native Electron launch. The specs are packed into
   role/name assertions, so they are the real acceptance gate for the rebuild and
   must be run screen by screen.
3. The retained `0.1.0-rc.2` receipt no longer verifies
   (`test_retained_product_and_evidence_inventory_matches_checkout`): any source
   change drifts a frozen candidate by design. A new labelled candidate
   (`0.1.0-rc.3`) is frozen at package completion, following the WP-057 pattern,
   not mid-rebuild.
4. Dark mode is defined in tokens but there is no theme switch in the shell.

## Limitations

Native Windows/Linux validation remains owner-run under the project-wide waiver.
No engine, content, contract or runtime-identity bytes changed.
