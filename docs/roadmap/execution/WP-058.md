## Scope

The owner asked for a complete replacement of the desktop presentation layer,
not a restyle: the renderer was React 19 with one 80-line hand-written
`desktop/renderer/style.css` (green-on-charcoal), 1 827 lines of TSX across
twelve screens, no Tailwind, no component library and no design tokens.

Design-system adoption is a rendering-layer change, so this package is
deliberately ordered foundation first, then screens, one commit per screen, with
the working tree building and the regression suite green at every commit.

## Decisions already made by the owner — do not re-litigate

| Decision | Value | How it was chosen |

| Green palette | **dropped** | owner instruction |
| Warm/neutral dark with amber | **rejected** | owner instruction |
| Blue canvas (the reference image's own wash) | **rejected as pastel** | owner instruction |
| Canvas | **violet, primary family** — `#F4EFFE → #BFA6E6` | owner picked option A from a rendered comparison sheet |
| Elevation | **"Lifted"** — three layers on `rgb(24 20 48)` | owner picked option C |
| Primary accent | `#2207D4`, sampled from the reference (hue 248°, sat 0.97) | accepted |

The canvas keeps the *curve shape* measured from the reference image (it holds
pale for most of the width and deepens late, rather than ramping linearly) but
none of its hue. Elevation is three low-opacity layers on a neutral-cool ink
`rgb(24 20 48)`, deliberately not tinted with the accent.

**Method note for the next session:** when the owner supplies a reference image,
measure it with PIL — per-column sampling for gradients, edge profiles for
shadows — and never interpolate from two samples. A rendered comparison sheet
(several labelled options on one PNG) converged in one round where prose
descriptions had failed three times; prefer it when taste is the open question.

## Delivered

### Foundation (first session)

- Tailwind v4 through `@tailwindcss/vite`; `components.json` registers the ReUI
  registry (`@reui` → `https://reui.io/r/{style}/{name}.json`) on the
  `radix-nova` style. Components install as owned source under `components/`.
- Design tokens (`desktop/renderer/style.css`) for the identity, light and dark,
  mapped through `@theme inline`.
- Inter bundled through `@fontsource-variable/inter`; no runtime font fetch, so
  the app stays offline and the packaged content policy is unchanged.
- Shell components: floating navigation rail (`AppShell`, `NavGroup`, `NavItem`),
  content blocks (`Panel`, `Stat`, `StateBadge`, `EmptyState`, `ErrorNote`,
  `LoadingRows`, `KeyValue`), and `NativeSelect`.
- `src.tsx` owns the active view so navigation lives in the shell; `workspace.tsx`
  keeps every existing contract, focus effect and page-scoped state.
- `@/*` resolves in vite, vitest and tsc (TypeScript 7 removed `baseUrl`; paths
  are configured without it).

### Second session (this one)

- `components/app/form.tsx`: `Field`, `CheckField`, `Toolbar`, `Actions`,
  `DataTable`, `Disclosure`, `Hint`, `SubHeading`. Labels wrap their control and
  selects stay native, so every accessible name the desktop specs drive is kept.
- `style.css`: one `.data-table` rhythm for every evidence table (wrapping cells,
  compact headers) and an exemption so checkbox and radio inputs never inherit
  the transitional form styling.
- `Panel` gained a `label` prop so a card can also be the landmark a spec
  addresses; `NavItem` gained `accessibleName`; `AppShell` gained a `skipLink`
  slot rendered before the rail; `NativeSelect` gained a `bare` variant for the
  world screen, which must contain exactly one `<svg>`.
- Screens rebuilt one commit each, in the agreed order: `overview`, `matrix`,
  `atlas`, `world`, `evidence`, `uncertainty`, `timeline`, `design-history`,
  `archives`, `interview`, `providers`, `recovery`.
- The transitional `.legacy-ui` layer now scopes to the optional assistant only;
  the workspace shell no longer applies it.

## Defects found in the previously delivered work

- `workspace.tsx` had lost four DOM hooks the desktop specs drive —
  `.domain-grid`, `.inquiry-guide`, `.workspace-layout` and the session-only
  `Purpose (optional, stays in this session)` field — plus the
  `N declared goals · N selected policies · N registered mechanisms` line and
  the full view names as navigation targets. All restored.
- The skip link sat after the navigation rail, so it was not the first tab stop.
  It is now rendered first in the shell.
- `tests/desktop/accessibility.spec.ts` asserted the retired dark theme's amber
  focus ring (`rgb(255, 213, 137)`). On the light violet canvas that colour sits
  at 1.6:1 against white and cannot serve as a focus indicator; the ring token
  `#2207d4` is 10.2:1. The assertion now expects `rgb(34, 7, 212)`, with the
  reason recorded beside it. **This is the one test edit in the package** and
  review should confirm it.

## Constraints the next session must keep

- The desktop regression specs drive the branch and scope pickers with
  `selectOption()`, so those two controls must stay real `<select>` elements
  (`NativeSelect`), not the registry listbox.
- Exactly one element may carry `role="status"` with the engine text; the specs
  match it strictly. Inside a screen, keep one status *slot* per region: several
  specs call `getByRole('status')` on a region and expect a single element.
- Unique button names: `Choose sandbox folder`, `Portable archives` and
  `Provider settings` each appear once.
- `world` must contain exactly one `<svg>` (the topology diagram) — the layout
  spec compares its markup before and after a re-seed, so its selects use the
  icon-free `bare` variant and the screen adds no icons.
- `page.getByRole('article')` addresses the workspace body, so screens must not
  add `<article>` elements; the provider catalog keeps its articles because that
  spec scopes them to the provider region.
- Tables the specs address by caption keep a real `<caption>`; lists they count
  keep one `<li>`/`<ol>` item per record with exactly one button each.

## Toolchain note

`npm run package` (and therefore `npm run test:desktop`) refuses to run on any
Node other than 24. This environment has Node 22.23.4, so packaging was run as
`npx -y node@24.19.0 scripts/desktop.mjs package`: the project's own guard still
applies, and nothing on the machine was changed. Playwright itself runs on the
system Node because it only launches the packaged binary.

## Limitations

Native Windows/Linux validation remains owner-run under the project-wide waiver.
A Linux run cannot certify Windows. No engine, content, contract, IPC or
runtime-identity bytes changed.
