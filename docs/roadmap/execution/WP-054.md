## Implementation and separate author inspection

`npm run dist` builds native Forge/PyInstaller output and creates a Windows ZIP
or Linux tarball with per-user script installers. Both reject an existing target,
verify payload hashes and run a bundled self-test before changing a launcher.
Versioned directories preserve prior applications; installers never open or
delete user data, transcripts, keys or selected civilization stores. Paths with
spaces are supported; line breaks are rejected. Failed installs retain their
new directory for diagnosis and leave the old launcher intact. These are per-user
script installers, not MSI/deb packages or automatic updates.

Native packaging rejects foreign OS/architectures to prevent shipping a host
Python runtime inside another target's Electron bundle. Distribution checks actual
x64 ELF/PE headers, permissions, direct Linux shared-library resolution, ASAR
identity and its production-only file inventory. Engine resources stay outside
ASAR. An ASAR containing an extra private file or the wrong version is rejected.
Symlinks are rejected before any bundled executable probe.

The self-test is a dedicated packaged entrypoint with fixed Decimal division/addition
and HMAC known answers, real SQLite cold reopen, identical operation retry without
a model, retained evidence, and archive export/import into a fresh store. It uses
only a fresh temporary directory, emits no paths or arbitrary errors, and never
loads a user civilization. Distribution runs it with an empty PATH. The installed
Electron scenario also uses an empty PATH through creation, cold restart and
reconnection, binding the tested behavior to the real bundled executable.

Optional Windows signing uses an external certificate-store key and signtool,
timestamps staged EXE/DLL/PYD files and verifies their Authenticode signatures.
Optional Linux signing uses an external GPG key and verifies its detached archive
signature. No key import/export or secret is introduced. Unsigned is explicit by
default; signing failures do not produce a successful receipt. Windows installer
script signing remains an organization-controlled separate step.

Each artifact retains file hashes/modes/sizes, app/ASAR/runtime identity, source
commit/dirty status, locks, contract/content digests, architecture/dependency and
probe results. The sidecar adds the archive checksum and optional signature hash.
This records a candidate; it does not claim bit-for-bit build reproducibility.
The manual native workflow builds/installs both current targets and runs the same
offline desktop/recovery/archive/provider/timeline checks without publishing.

Separate author inspection traced native admission, source/resource resolution,
checks before execution, external signing boundaries, no-data installer behavior,
exclusive destination creation, shortcut replacement and rollback instructions.
See [the owner guide](../../native_distribution.md) for platform dependencies,
secure-key/proxy/cancellation tests, signing, install/uninstall and limitations.
