## Implemented behavior and supported bounds

Canonical optional text/image/audio parts preserve text contract compatibility.
Session attachments carry provenance, original MIME/size/hash, classification,
explicit this-turn consent and session retention. Main verifies original bytes,
bounded extraction, known-model accounting, every fallback and output path before
preparation. The UI clears selected files/consent after preparation, binds inclusion
metadata into immutable request context, and reviews the exact complete provider
payload before each dispatch. Python spending remains unchanged and mandatory.

[The matrix](../../assistant_modalities.md) records every input/output modality,
including explicit unavailable combinations. Supported paths are text/local UTF-8
excerpts, low-detail bounded PNG inputs on known GPT-4o models, bounded canonical
WAV input/output on known OpenAI audio models, and streamed private WAV artifacts.
No passive image/audio/video renderer or decoder was enabled. A user may save an
artifact through a main-owned dialog into a new file; originals, excerpts and
artifacts remain session-owned until explicit external export.

Current public OpenRouter documentation requires streamed audio and a dedicated
image generation API. Image generation, video/PDF processing, unknown tokenizer
families, arbitrary codecs/URLs and generic compatible multimodal endpoints are
therefore visibly unavailable in this bounded adapter. They are rejected before
sharing, not silently converted/dropped or certified by synthetic fixtures. This
is not universal provider-modality support and does not complete G6/M6.

Opaque indexed reasoning strings/metadata are retained separately from visible
reasoning, without decryption or interpretation. Only completed responses can
supply continuation history. Main revalidates original model identity, exact
endpoint/profile revision and a single pinned provider with fallbacks disabled;
incompatible history requires a fresh request. Complete continuation bytes remain
inside exact-payload review and cumulative disclosure/spending bounds.

Turn deletion revokes and aborts the entire lineage and removes all active raw
content, artifacts, opaque details and prepared child references. Late output
cannot restore the registry. Reports/history/archives never receive these raw
session objects; durable spending identities/hashes/exposure remain. File exports
explicitly transferred to user ownership remain outside session deletion. Private
attachment turns cannot enter proposal tools or immutable simulation records.
