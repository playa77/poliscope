## Full acceptance

- Timeline workspace: create/open experiments, opening and current confirmed
  boundary, actual sparse checkpoint identity, paginated retained states and
  traces, event/adoption origin and consequences, bounded progress and durable
  pause/resume/cancel. A displayed range never schedules or executes boundaries.
- Future policy scheduling: choose an accepted parent/child policy revision and
  future simulation day. The engine derives only explicit policy binding deltas,
  previews effective scopes, replacement values, binding preconditions and provenance, and then forks a new future from the current
  confirmed head. Existing run history and dynamic state are preserved.
- Past-state forks: choose a retained sequence and a distinct experiment ID.
  Opening day/state and origin differ visibly from future scheduling. Preserved
  or explicitly new stochastic realization policy is passed to the real controller.
- Comparison: retained local/group outcomes, exact compatible deltas and changed
  opening choices/conditions, assumptions, policies, schedules, realization and
  scope/model/runtime semantics. Incompatible clocks/models/scopes/coverage
  withhold subtraction. Missing evidence/outcomes remain unavailable, never zero.
- Presentation: selectable indicator time series with accessible exact-decimal
  tables; declared probability-weight charts and distribution/assumption tables,
  distinct from realized draws. Unsupported dynamic models stay visible.

## Implementation and boundaries

Python owns all simulation, policy delta derivation, comparison arithmetic and
SQLite writes. `contracts.timeline_workspace` generates the bounded desktop DTOs.
A named `timeline:request` grant validates sender, schema, selected revision/store/
civilization and echoed response context. The renderer receives no path, SQL,
arbitrary IPC, runtime callbacks or code activation authority. Optional input
fields normalize before request/reply binding. Text and retained traces render
inertly, without remote resources.

The presentation command ledger binds each mutation intent to its entire payload.
Controller operations retain their own atomic boundary/evidence/checkpoint
outcomes; retries recover those before any stale-head check. The wrapper can
recover an uncertain response between the controller commit and directory/result
publication. It never displays a private candidate as saved. Ten-boundary chunks
allow pause/cancel between commands; prior confirmed work survives terminal cancel.

New workspace designs use `fixed-364-v1`; existing saved calendars are untouched.
Unsupported historical clocks fail explicitly. The normal starting workspace has
no reviewed activated dynamic mechanisms. Its time-only trajectory is labeled
accordingly; the production service does not install the synthetic test callbacks.
Native source activation and scientific validity are separate open work.
