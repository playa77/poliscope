## Scope and acceptance

Implement a bounded host-only static education/training capacity interface.
Explicit service prerequisites link canonical participant/staff cohorts, declared
qualification evidence, positive student/staff/supply claims and facility assets.
All staff/student/care demands share DOM-02's single dated cohort budget. Facility
slots use the canonical allocator in a separate disjoint resource pool with one
capacity account per asset/period. Both pools retain competing claims, reservations
and prior postings. They allocate independently: these are input commitments,
not synchronized attendance or delivered teaching. A service is capacity-ready
only when all its prerequisites have no unmet demand and eligibility, declared
qualification and selected authority are known. No resource refund or hidden
rescheduling is inferred when another prerequisite fails.

Use actual WP-013 policy resolution; retain unknowns and conflicts. Validate
scope, cohort roles, asset/account uniqueness, positive requirements, mapping and
cross-pool disjointness. Return detached reports with full prior/additional/unmet
account evidence. No allocator/arithmetic/resolver copy, state writes or automatic
skills/learning effects. Contracts v1, hypothetical and unactivated.

Validation: frozen installs, focused/full Python, generated/content checks,
typecheck, desktop units/roadmap, Linux package and packaged selection where
