## Implemented behavior and parent evidence route

The previous scheduling service could plan boundaries and the boundary store
could persist validated data, but neither reduced real transition proposals.
`TransitionReducer` now stages current events/policies, resolves explicit
preconditions and reviewed typed adapters, collects all demands before one finite
allocation, stages owned effects from actuals, checks exact balances/model
invariants, and recomputes the full candidate before the provider's atomic commit.

The plan explicitly selects priority, carry precedence, account/value mappings and
runtime quotas. No rule is selected by domain name, input ordering, calendar
presentation or a player's goal. Typed physical views restrict declared reads and
exclude goals, notes and diagnostic targets. Policy reads use the shared resolver,
including conflict/missing values. Transition-only instances need no fictitious
static procedure. Unsupported graphs/adapters, missing native models and unresolved
prerequisites remain explicit, rather than instant effects.

Active books carry exact closings and remaining reservations/demand, not fresh
openings. Fulfilled entries remain in immutable prior receipts instead of creating
an active-book horizon. Owned claims retain original requested and prior-fulfilled
quantities. Known terms and coefficients cannot be reauthorized by a model;
unknown access/funding can be refined only explicitly against the prior choice
digest. Paused multirate owners retain their terms. Posting IDs are boundary-local.

The shared conformance harness now exercises selected hypothetical construction,
maintenance, education/skills, service queues, population/health, ecological state,
institutional cases and response capacity. Literal values/bounds in
`tests/fixtures/domains/transitions-v1.json` are artificial test models, not native
construction, learning, treatment, demographic, ecological or rescue predictions.
All twelve domain adapters have paired synthetic conformance cases. The actual
retained twelve-domain/static-counterpart fixture also executes through real
revisions, scheduling and boundary confirmation, with every absent native
transition still labeled a gap. No source branch or source activation is promoted.

Validation covers shared finite material/work and product/residual/loss balances;
selected reverse order; unknown/denied prerequisites and conflicts; typed policy
resolution; inactive owners and pending refinements; quantum, alias, ownership,
precision, time, goal isolation and callback purity failures; invalid model
invariants and actual closing static implementation/solver failure; every private
cancellation checkpoint; every storage write; real process exits immediately
before/after COMMIT; cold completed replay; original v1 state/operation identity;
bounded chunks/progress/coverage; a real 364-boundary year retaining an intermediate
daily shortage; and 1,200 fulfilled jobs without active history accumulation.
