## Implementation and separate author inspection

Profiles retain explicit endpoint identity, open model IDs, generation/routing and
unverified capability preferences separately from main-only credential references.
Named schema-checked IPC is authorized against the live window/frame/document;
renderer requests cannot supply a network URL, method, header or filesystem path.
Temporary password inputs clear before awaiting the one-time transfer. Unsaved
endpoint/preference changes disable entry/testing, and the saved destination is
visible. No credential reply or automatic key-transfer retry exists.

Main calls Electron safeStorage, refuses Linux `basic_text`, and uses session-only
memory for unavailable protection. Endpoint/profile/kind binding is inside the
ciphertext. Missing, corrupt or copied blobs do not authenticate another profile.
Protected material stays in the approved app provider store; nonsecret profile
files hold references only. Keys and encrypted blobs are absent from civilization
SQLite, export projections and Python's allowlisted child environments. A real
export test selects the same directory as the provider store and verifies the
uncompressed portable contents as well as the database exclude credentials,
blobs and provider-only preferences. Session-only restart forgets keys.

Electron net uses an isolated memory session and Chromium/system proxy behavior;
renderer CSP and passive-load denial remain intact. Metadata tests send only a
fixed GET and explicit Bearer header, without cookies or interactive credentials.
All redirects abort before another request; response bodies/headers never become
UI diagnostics. The real packaged test confirms no request reaches the redirect
sink, no cookie returns, hostile auth bodies are suppressed and key removal aborts
an in-flight connection. HTTP success is labeled only as metadata acceptance, not
proof of key validity, model access or generation support.

Profile changes, replacement, removal and shutdown revoke in-flight tests before
awaiting persistence. Tests wait outside the mutation queue so removal can run.
Key commands use expected profile revisions; stale requests cannot silently
replace a changed credential. Writes use exclusive staging, owner-only file
permissions, file flush and atomic rename. Startup removes only matching orphan
key staging files left by interrupted writes. A failed delete/write reports
failure; it does not advertise successful removal or write a plaintext fallback.
Shutdown aborts sockets immediately and bounds settings-I/O waiting at 1.5 seconds.

The separate author inspection traced UI → preload → authorized IPC → generated
DTOs → settings/vault → fixed transport and back through bounded status-only
replies. It also inspected process environments, export readers, lifecycle and
all failure branches. It found and addressed unsaved endpoint/key ambiguity,
interrupted encrypted staging cleanup and the shutdown wait bound. No
independent reviewer was allocated: **solo-validated; agent review deferred**.
