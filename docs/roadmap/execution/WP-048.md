## Implemented behavior

The existing FULL-durability SQLite ledger migrates additively. Each dispatch
retains its immutable reservation binding, known catalog estimate inputs/source/
observation time, original provider endpoint/model references, reported token
categories, completion/cancellation outcome, generation ID and reported USD cost.
No prompts, attachments, credentials or opaque reasoning enter this ledger.
Python Decimal28 performs catalog arithmetic and aggregation with an independent
exact Fraction check. Provider monetary JSON lexemes are preserved before binary
number parsing, including exponent notation, only at documented monetary paths.
Opaque continuation fields retain their original value types. Costs retain up to 18 decimal places;
reservations and configured allowances retain the existing microUSD quantum.

Known actual replaces that dispatch's reserved exposure in every applicable
turn/session/profile total. A reported zero is distinct from missing actual. Usage
without actual, cancellation, lost acknowledgments and crashes retain the bound;
completion alone never releases it. Replayed observations and grants cannot add a
second charge. Conflicting observations retain an audit trail and visible flag;
conflicting lower costs do not free allowance, while a higher known cost for the
same generation increases counted exposure. Provider overruns can exceed local
limits and then block new requests. Account-side limits remain the hard control.

Only unambiguous single-model text token/request catalog prices receive a catalog
estimate. Fallback, multimodal, additional-price-category, malformed or unavailable
pricing, including an absent request-rate declaration, remains explicitly unknown and requires the existing bounded-exposure
policy. A known catalog estimate exceeding the chosen bound denies reservation.
Neither catalog prices nor local bounds are represented as a provider quote.

Main offers explicit OpenRouter `GET /generation?id=...` retrieval with the
current matching profile endpoint and an active key lease; no prompt/history is
sent. Identity mismatches, redirects, malformed metadata, revoked keys and generic
compatible-provider cost semantics cannot falsely resolve USD exposure. Returned
metadata is allowlisted and credential-echo checked. Native and normalized token
counts remain separate. Public endpoint documentation was verified at
<https://openrouter.ai/docs/api/api-reference/generations/get-generation>.

Visible controls show reported actual, catalog estimate, counted scope totals,
unresolved requests and conflicts. Explicit updates can raise/lower allowances
without resetting charges, including recovery after a denied dispatch. A bounded,
profile-scoped, paginated charge history retains non-content references across
restart and transcript deletion. Selecting/reviewing the current profile allows
stored generation reconciliation without any new generation dispatch, including
after deliberately restoring a session-only key. Old reservations created before
this package lack reconstructible request references; they remain visible as
legacy counts and their exposure stays counted. No references are fabricated.
