## Behavior and acceptance

`Experiments` adds typed trusted-host create, retrospective fork, advance, durable
pause/resume/cancel, status and query operations over the actual boundary provider.
An immutable controller manifest retains checkpoint spacing (in confirmed boundary
counts), fork source and realization policy. Durable control records have optimistic
sequence checks. Cancellation of the experiment is terminal; a new experiment fork
can continue it. A chunk cancellation hook leaves every confirmed boundary intact;
resuming a cancelled chunk uses a new operation ID from its returned head.

Bounded advances retain the complete command binding before execution and deterministic
child operation IDs. Retries recover confirmed child outcomes before head, control,
model or cancellation checks. Exact completed retries work without executable models.
Status returns unknown, running confirmed progress, or the final durable outcome.
Reusing any controller operation ID for another payload/action fails closed, including
an unfinished advance. Progress callbacks see committed data only; losing a callback
or process does not lose or repeat advancement.

Each configured checkpoint index is written by the provider's trusted transaction
hook alongside the boundary, canonical state, accepted-result closure and exact
child operation outcome. The immutable journal is the head; no separately published
mutable head can get ahead of durable confirmation. Hook/control/storage failure
rolls the entire boundary transaction back. Controlled experiments require the
controller hook even when accessed through a bare transition host. Old uncontrolled
provider clients preserve their existing behavior.

All snapshots, event/adoption outcomes, transition receipts, draws, assumptions,
model identities and explanation closures remain retained independently of sparse
checkpoint indexes and disposable caches. Pagination bounds checkpoint queries.
Recorded replay selects the nearest checkpoint and checks intervening ordered
boundary links, due schedules, policy/event/conflict outcomes, conditions and every
retained state/evidence identity. It does not execute today's models. Verification
replay starts at a preceding checkpoint and independently reduces intervening
boundaries using the retained draws, validating sampler/runtime identities and
comparing the complete canonical input, receipt and evidence digests. Missing
historical runtime or a changed result fails explicitly; there is no substitution
of current output for old evidence. Replay is bounded and cancellable and writes
nothing.

Retrospective forks copy the selected confirmed snapshot, including physical stocks,
pending claims/reservations and that boundary's evidence, without resetting it to
the design revision. The opening retains an explicit immutable source-boundary
identity distinct from design-counterfactual lineage. Source state and evidence
identities are checked on historical reads. The first child reduction carries the
actual parent receipt into the newly approved future plan. Future events/adoptions
can be edited after the fork day, preserving their normal validation/approval rules.
Mechanism schedule identities remain fixed in this v1 service; new mechanisms or
schedule migrations need a separate supported model transition. Paired forks retain
stable instance/event/draw identities and seed. Explicit `new_realization` forks
retain the selected past state and declare a new seed for subsequent realizations.
Neither policy rewrites the parent experiment.

## Limits and next action

The APIs are trusted-host engine services; Electron UI and renderer authorization
are separate work. Checkpoints are retained indexes into content-addressed full
boundary snapshots, rather than a delta-compression format. Quotas bound replay
and advancement without selecting a narrative horizon. Old runtime readability
and executable reproduction are separate decisions. Retrospective edits apply
strictly after the selected state, and neither past facts nor approved choices
are silently changed. Source activation and native scientific models remain as
qualified before this package. After full validation and review, publish one regular
PR against main; do not merge without user authorization. Reassess subsequent
roadmap prerequisites from current main after acceptance.
