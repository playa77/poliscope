## Implemented audit

`scripts/audit_product_gate.py` overlays the immutable baseline leaf ledger. It
retains all 1,053 leaves, verification owners, first gates and supporting package
records; enumerates all 30 G7 subcases and 14 regression obligations; and reads
all twelve current domain coverage files with hashes, source identities,
activation, static/transition counts and evidence classifications. It deliberately
never infers scientific validity or product acceptance from an inventory.

Optional evidence must match the current source candidate and retained artifact
hashes. Passing production evidence requires exact JUnit targets, no missing,
duplicate, failing or skipped target, no collection errors, and a separate
production-service inspection. RT passes additionally require their linked
scenarios and their own evidence. Unknown IDs and requirement-source drift fail.
A report cannot promote unrelated leaves or implicitly satisfy native/provider
outcomes. The auditor is a completeness tool; inspection prose remains a human/
agent attestation, not independently authenticated proof of behavior.

Generate the gap ledger using:

```sh
uv run --frozen python scripts/audit_product_gate.py --output artifacts/product-gate.json
```

Create the output directory first. `--evidence` accepts a JSON object with a
`candidate` from `scripts/evidence.py` and `requirements`, `cases`, `regressions`
maps keyed by stable ID. Each executed entry has `outcome`, `owner`, `reason`,
`candidate`, `artifacts` (`path`, SHA-256; JUnit reports also `format: junit`),
and for a pass `tests` (exact testcase names) and `production_inspection`.
Keep reports/output under ignored `artifacts/` so they do not change the candidate.
