# Poliscope 0.1.0 release candidate 2

Prepared 2026-11-08 as the corrective maintenance delivery [WP-057](../../roadmap/execution/WP-057.md)
on top of merged `0.1.0-rc.1` (source `64d9aed`, delivery PR #129 merge `51664d0`).
The application still identifies itself as **0.1.0**; the `rc.2` label identifies
this handoff without changing the application version. This is an unsigned
educational prototype candidate. No release, signing, upload to a release
channel or merge is authorized by preparation, and no native artifact has been
built for this label yet; the owner-run native workflow decides that separately.

## Corrections relative to rc.1

1. Linux user-namespace-restricted distributions (Ubuntu 24.04+, Xubuntu):
   documented the silent first-launch sandbox failure with its two sanctioned
   administrator remedies, and made the installer surface the failure mode at
   install time through a non-fatal NOTE (`packaging/sandbox-notice.sh`, driven
   by the same sysctl parameters the validation used). The installer still
   requires no administrator account and never bypasses a sandbox.
2. The Linux candidate now bundles a launcher icon (`packaging/icons`,
   generated by `scripts/make_icon.py`) and the installed launcher uses it
   (`Icon=poliscope`, installed into the user's hicolor icon directory).
   Installer failures and the documented upgrade rules are unchanged.

## What did not change

Engine and desktop application code, content, contracts, dependency locks and
the numeric/runtime identities are unchanged relative to rc.1. The [rc.1
record](../0.1.0-rc.1/README.md) therefore carries this candidate's behavior,
model, performance, provider, scientific and owner-validation scope unchanged;
its explicit limitation claims are not re-evaluated by this packaging
correction. Windows still gets no embedded icon change; that remains owner-run
work.

## Freezing and current receipt

[The current inventory](inventory.ci-history.json) freezes every product,
schema, content, lock, packaging input, WP-055 evidence and requirement source
by path, size and SHA-256 at this delivery's commit. Verify the checkout against
it with `uv run --frozen python scripts/freeze_release.py --check`. A different
label uses `--label <candidate>` with a fresh release directory; receipts are
never overwritten or relabeled in place. The [rc.1
receipts](../0.1.0-rc.1/README.md) remain immutable. Scope, provenance and the
publication boundary follow [native distribution](../../native_distribution.md);
execution evidence and change accounting live in the [execution
ledger](../../roadmap/execution/README.md) and [WP-057](../../roadmap/execution/WP-057.md).
