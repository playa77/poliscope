# Communication prerequisites

`evaluate_communication` is a pure host-only adapter over canonical assets,
institutions, directed information-channel relationships and one finite account
book. Explicit recorded/available, publication/receipt access, disclosure,
availability and delay inputs gate message-slot commitments. Optional named
verification consumes a separate finite slot atomically. Evidence retains the
complete request, staged postings, holds and unmet quantities.

All arithmetic belongs to the existing allocator/account book. Output indicates
capacity readiness only: no message delivery, verification result, truth/trust
score, wall-clock timing or policy enforcement. Delay is a retained declaration,
not an executed transition. Message bodies and application private payloads are
outside this contract. No network access, IPC activation or mutable domain state.
See the execution record for remaining parent acceptance and actual consumers.

`exploration` offers explicit settlement/region queue interviews and detached
previews bound to the complete host context. No option is selected by default.
`coverage` reconciles every pinned DOM-09 source row and provenance choice;
partial slot prerequisites do not activate source models, deliver messages,
verify truth or resolve privacy policy. Other branches remain unsupported.

The governance-owned [DOM-03/09 counterpart](../governance/communication.py)
uses actual scoped approval as an explicit message publication prerequisite.
Each claim declares dependence or independence and dependent claims name the
exact decision target and affected slot accounts. Approval grants no access or
disclosure exception. Channel and optional verification commitments remain one
finite dated book, disjoint from canonical administrative time. Both original
preflight and restricted evaluation remain inspectable; only a complete resolved
pair has a private two-book candidate. Neither delay nor capacity readiness means
delivery, publication, verification of truth or institutional response.

The maintained DOM-04/09 counterpart is hosted by
[`law_conflict.communication`](../law_conflict/communication.py). It evaluates
finite case work before explicit message prerequisites, preserving original
reach, disclosure, access, delay and channel/verification limits. Legal dependence
binds a cohort recipient, channel controller/asset, obligations and affected
accounts; null case IDs declare independence. It neither delivers nor publishes
messages. See [execution evidence](../../../../docs/roadmap/execution/WP-032-counterparts-adjudication-communication.md).
